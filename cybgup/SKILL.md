# 初研报告研判技能（CYBGUP）

撰写国资"以投促招"项目的初步研判报告。用于见企业前的预判：不等企业补料，用BP+联网搜索+行业推断把判断做完。产出对标历史成稿样稿的专业水准：事实陈述与研判判断分层，每个结论有数据与行业对标支撑，结论具备可指导下一步动作的评级与建议。

## 一、核心铁律（违反任一条即不合格）

1. **不轻信企业材料**：推介资料/访谈是"企业自述"，非事实。每个关键事实须用公开信息（企查查/工商/财报/招投标/官网）交叉核验，矛盾点直接点破。
2. **事实与判断分层**：报告前半部分"基本情况"只陈述可核实事实并标注来源；后半部分"初步研判"才下判断。判断必须基于前文事实，不凭空推断。
3. **反向校验优先**：不照抄企业承诺。产值承诺要用行业市场容量、爬坡规律、历史业绩三方对撞；"首创/空白"要找竞品反证；估值要对标可比公司。
4. **证据三级标注**：每个关键数据按可信度标注——【已查证】（联网核实的公开信息，标来源+年份）/【企业自述】（BP/访谈提供的数据）/【推断】（基于行业知识或专业判断推理的，标【推断】并附推导依据）。不用【待核验】——本技能用于见企业前预判，不等企业补料。查不到的要么推断要么不写，不把待核验拖到正文里。
5. **结论工作导向**：不写"建议进一步了解"这类空话。给出 A/B/C/D 评级 + 具体下一步动作（暂缓/继续跟进/进入尽调/推荐外部机构/纳入储备库）+ 会面时需重点核实的事项（带着研判结论和具体问题去见企业，而不是空手去）。
6. **国资合规兜底**：凡涉投资金额、基金出资、国资审批，必查"以投促招"政策符合性、审批权限、六大合规红线；涉外资/港股必查资金出境路径。
7. **先查证、再推断、后落笔**：禁止未经尝试即放弃。凡联网可核验项必须先查（见下文"验证引擎"）；查不到的优先用行业知识/专业判断推断并标【推断】+推导依据；推断不了的不写——但如果该维度影响研判结论，必须在研判部分标明信息盲区及假设。满屏【待核验】或全靠企业自述=验证未执行，不合格。
8. **搜不到≠不存在**：第一次搜索没结果不等于信息不存在。必须穷尽搜索策略（见"验证引擎"搜索兜底机制）后才能下结论。把"我没搜到"当成"公司零公开足迹"写进报告是严重错误。

## 二、工作流（5步）

### 第1步 读取输入，判断项目阶段
- 读用户提供材料：企业资料、项目档案、会议纪要、行业资料。
- 判断项目阶段：**成熟期**（有规模营收/利润、看估值盈利质量退出落地）/ **成长期**（增长中、看增长性客户验证融资节奏）/ **早期**（收入小、看技术真实性团队能力工程化路径后续融资）。阶段决定研判重点，不混用标准。
- 材料缺关键项不阻塞——本技能用于见企业前的预判，不等企业补料。缺什么按三层处理：能查的查（第一层查证），查不到的用行业知识推（第二层推断），推不了的不写（第三层盲区，关键维度在研判里标出）。先跑"验证引擎"第一层，能联网查的当场查掉。

### 第2步 逐维度研判（按下文"20维度速查表"）
- 必做维度：01工商、05主营、07技术、08财务、09融资落地、10行业市场、12竞争、15估值、17合规、20地方匹配（每个项目必过）。
- 条件触发维度：有子公司/股东→03、04；有财报→16财务健康度；制造业→17环保专项；外资/港股→19出境；早期项目→06团队加重。
- 某维度需详细打法（动作步骤、三问验证、陷阱、自检）时，读 [references/dimension-playbook.md](references/dimension-playbook.md)，按维度编号定位章节。

### 第3步 交叉验证，识别红线与画饼
- 把企业承诺（产值/份额/增长）逐一与行业容量、同业实际、企业历史对撞。
- 扫红线：失信/限高/冻结（17）、国资六大红线（19）、现金短债比<1（16）。命中任一触发否决评估。

### 第4步 组装成稿
- 按 [assets/report-skeleton.md](assets/report-skeleton.md) 的完整骨架输出。
- 抬头单位 + 保密提示 + 基本情况（事实）+ 初步研判（判断）+ 总结评级（引政策依据）+ 落款。

### 第5步 交付前自检
- 跑下文"交付前自检清单"。
- 自检不通过的，补强后再交。宁可标【推断】或指明盲区，不要编造数据。

## 验证引擎：查证 → 推断 → 盲区

本技能用于见企业前的预判。不等企业补料，不出现"待补充材料清单"。每个维度按三层处理：能查的查、能推的推、推不了的关键维度标盲区。

### 搜索工具优先级（关键！用错工具等于没查）

**优先级1·浏览器自动化**（首选，效果最好）：
用 Playwright/Puppeteer 控制真实浏览器（Chrome/Edge），模拟真人访问目标网站。能绕过反爬、读取JS渲染后的页面内容。
```
Node.js: playwright-core + 本机 Chrome
Python: selenium / playwright
```
适合：企查查、天眼查、36氪、公司官网、Google Patents、招聘网站等需要JS渲染的页面。

**优先级2·HTTP请求库**（次选，速度快）：
用 Python requests 或 Node.js axios 直接抓取页面HTML，解析正文。新闻类、专利类网站通常不需要JS渲染。
```
Python: requests + BeautifulSoup4
```
适合：36氪、证券时报、IT之家、Google Patents等新闻/数据页面。

**优先级3·搜索引擎API**（兜底，质量最差）：
直接抓取 Bing/Google 搜索结果页。中文搜索质量不稳定，仅作为发现线索的手段，不作为最终信息来源。
```
Python: requests 抓 Bing/Google HTML → 正则提取
```
注意：搜索引擎返回的结果质量远不如直接访问目标网站，容易返回字典释义等无关内容。

### 搜索兜底机制（搜不到时怎么办，关键！）

第一次搜索没结果，禁止直接下"公司零公开信息"的结论。按以下策略逐个尝试：

**策略1·换公司全称**：BP里的简称可能搜不到，尝试"XX科技有限公司""XX信息科技有限公司"等工商主体全称。从BP版权页、官网备案信息找公司全称。

**策略2·搜产品域名**：BP里提到的产品名、官网URL、APP名都是搜索入口。如 unrush.music→搜 unrush music player；boyamus.com→直接访问该域名。

**策略3·搜投资人组合**：从BP中提取已知名的投资人，搜"投资人名+行业关键词"，如"奇绩创坛 音乐 AI"。

**策略4·搜创始人+学校/荣誉**：搜"创始人名+学校名""创始人名+荣誉名称"，如"殷渝杰 北邮""殷渝杰 互联网+大赛"。

**策略5·拼音搜索**：中文公司名搜不到时，试拼音/英文。如 qiyin、qiyin tech。

**策略6·直接访问已知信息源**：36氪（36kr.com）、企查查（qcc.com）、天眼查（tianyancha.com）、IT桔子、Google Patents、GitHub、Hugging Face——直接去这些网站搜公司名。

穷尽以上策略仍无结果，才可标注"已穷尽搜索策略未果"。此时仍不可断言"公司无公开信息"，应标注"以现有搜索条件未检索到"。

### 第一层 查证（必须先跑）

| 核验项 | 搜索策略 | 命中后处理 |
|-|-|-|
| 工商五要素 | 直接访问企查查/天眼查/36氪PitchHub搜公司名；或搜"公司全称 工商" | 查到则正文写"根据公开信息（企查查，2025年），公司成立于X年，注册资本X万"标【已查证】 |
| 参保人数 | 企查查/天眼查工商年报数据 | 查到则与企业自述团队规模做反差分析 |
| 失信/限高/被执行 | 企查查/天眼查/中国执行信息公开网搜公司名+实控人 | 命中=红线，触发否决评估 |
| 股权冻结/质押 | 企查查/天眼查司法风险栏 | 命中=硬雷 |
| 专利 | Google Patents（patents.google.com）搜公司全称；或中国国家知识产权局 | 查有效/无效、发明占比、专利权人 |
| "首创/全球首个"反证 | 搜产品关键词+已知竞品名 | 找到竞品即打脸 |
| 行业市场数据 | 搜"细分赛道+市场规模+第三方机构名"（弗若斯特/灼识/IDC/IFPI） | 标来源可信度，与产值承诺对撞 |
| 竞品与集中度 | 搜"细分赛道+头部公司+市占率" | 锚定2-3家可比公司，做竞争格局表 |
| 媒体报道 | 36氪/证券时报/IT之家等搜公司名 | 验证融资历史、产品发布、业务描述 |
| 开源/学术 | GitHub/Hugging Face/Google Scholar搜公司名或产品名 | 验证技术真实性 |

执行时每个搜索策略都要实际尝试；查到即标【已查证】+来源+年份；查不到进入兜底机制（换策略重试），穷尽后才进入第二层。

### 第二层 推断（查证未果，但行业知识或专业判断能推导）

查不到的数据，如果行业常识、同业规律、产业链逻辑能支撑一个合理判断，就写出来——但必须标注。推断不是猜，必须有推导链。

格式：正文写出推断结论，句末标【推断】，括号内附推导依据。
示例："公司当前可能仍处于亏损阶段【推断：自述收入1000万配近百人团队，按一线城市人均成本30至40万每年推算，年人力支出约3000至4000万，远超收入】"

常见可推断场景（按维度）：

- **D01 工商→规模反差**：参保人数 vs 企业自述员工数/业务规模。例：企业称100人但参保12人=外包严重或规模注水。
- **D05 主营→收入结构**：BP讲故事但无收入拆分，可据产品定价×目标用户量推算理论收入天花板。
- **D07 技术→成熟度**：有专利结构（发明占比高=硬技术）+产品是否上线，推断工程化程度。
- **D08/D16 财务→盈亏方向**：有收入+团队规模，按行业人均成本推算人力支出，判断大致盈亏。
- **D09/D18 落地→产值合理性**：有产能规划+行业单产数据+历史业绩，推算产值可达性。
- **D10 市场→隐含市占率**：产值承诺÷细分市场规模=隐含市占率。>30%质疑，>100%证伪。
- **D12 竞争→公司位势**：有头部公司营收/市占率，对比企业自述数据，推断领先/并跑/落后。
- **D15 估值→合理性**：有历史融资轮次+可比公司PS/PE，推算合理估值区间。
- **D20 地方→贡献可达性**：有产值规划+行业税负率+就业密度，推算税收与就业贡献的合理性。

推断的质量标准：推导链可复现（读者跟着推导过程能算出同样结论），不是"感觉应该"。

### 第三层 盲区（查不到也推不了）

- 该维度不影响核心研判，则不写（沉默优于噪音）
- 该维度影响研判结论，则必须在"初步研判"部分标出盲区，格式：
  "该维度因现有材料不足无法判断。若XXXX，则存在YYYY风险。建议会面时重点核实ZZZZ。"
- 不在"基本情况"部分留空或标"待核验"——基本情况只写有内容的东西

### 执行顺序（硬性）

1. 先跑第一层全部可查项（用浏览器优先策略，穷尽兜底机制）
2. 第一层未覆盖的，逐项判断能否推断（第二层）
3. 推不了的，判断是否影响核心研判（第三层）
4. 三层跑完，才动笔写报告
5. 报告正文每个数据：要么【已查证】带来源，要么【推断】带推导依据，要么不出现——没有第四种状态

## 前后端分层：工作底稿 vs 成品报告

研判分两层产物。**后端=工作底稿（AI内部，用户不看），前端=成品报告（交付用户）。** 两层不可混写。

### 后端：研判工作底稿（内部中间态，不交付）

- 逐维度的验证记录（用了什么策略、查到什么、来源链接）
- 对撞算式中间步骤
- 竞品反证的搜索结果原文
- 维度触发判断
- 自检清单逐项结果
- 概念认知引用（判断标准，是给AI的尺子）

工作底稿在AI内部完成，用于支撑报告结论。**其内容不得直接出现在成品报告里。**

### 前端：成品报告（交付用户）

- **事实层**：已核验的事实+来源（后端验证后的结论，非搜索过程）
- **判断层**：基于事实的研判论证
- **评级与建议**：A/B/C/D+具体下一步+会面核实要点
- **会面核实要点**：推断项已写进正文标【推断】；盲区已在研判标出；会面时需重点核实的事项集中列出

### 不可混写的红线

- 报告正文不出现维度编号（D01/D07）——这是内部索引
- 报告不出现自检过程
- 报告不对用户说教概念
- 报告不出现工具调用痕迹（"搜索了XXX"）
- 报告正文不出现【待核验】——查到的标【已查证】，推出来的标【推断】，查不到也推不了的要么不写要么在研判标盲区

## 三、20维度研判速查表

速查只给核心动作与关键认知。详细动作清单、三问验证、陷阱、自检见 [references/dimension-playbook.md](references/dimension-playbook.md)。

| # | 维度 | 核心动作 | 关键认知（打假点） | 触发等级 |
|-|-|-|-|-|
| 01 | 工商信息 | 五要素采集；参保反推真实规模；实缴比例；变更频次；曾用名/摘牌史 | 注册资本≠实力，参保人数≈真实规模；实缴<10%质疑 | 必做 |
| 02 | 股权结构 | 全景穿透找实控人；机构股东四级分级；融资估值曲线；质押冻结代持 | 持股≠控制权，穿透算表决权；质押/冻结=硬雷 | 必做 |
| 03 | 对外投资 | 子/孙/参股全景四要素；异常主体识别（未经营/清算/涉案）；空壳追问 | 未经营子公司可能是壳 | 有子公司必做 |
| 04 | 关联关系 | 关联营收占比3年趋势；资源混同（地址/人员/品牌/资金）；同业竞争 | 关联>30%警惕，>60%独立性存疑 | 有大股东/产业资本必做 |
| 05 | 主营业务 | 企业自述vs公开信息双源核对；收入结构拆主力vs故事线；客户集中度；业务演变 | 企业自述≠事实；频繁转型=包装新概念 | 必做 |
| 06 | 创始人团队 | 履历三查（学历/任职/创业史）；技术对口度；荣誉验官方公示；团队完整性 | "曾任/参与"模糊表述要核实；荣誉查不到公示不加分 | 早期项目加重 |
| 07 | 技术与专利 | 专利三看（有效/无效、发明占比、对应业务）；"首创空白"找竞品反证；壁垒分级 | 专利数≠实力，无效占比高是重点；"国内空白"必被打脸 | 必做 |
| 08 | 财务情况 | 三年营收/净利/毛利率趋势；毛利率行业对标；应收占比周转；经营现金流 | 营收增长≠健康；有利润没现金的公司很多 | 有数据必做 |
| 09 | 融资与落地 | 融资诉求拆解；估值PS/PE对标；产值三重验证；落地载体与企业自投；地方贡献量化 | 产值规划≠能兑现；没做过10亿却承诺50亿=画饼 | 必做 |
| 10 | 行业市场规模 | 总市场→细分逐层拆；产值÷细分规模=隐含市占率；可达性；数据源可信度 | 大市场≠可触达市场；承诺÷细分>100%直接证伪 | 必做 |
| 11 | 行业增速阶段 | 多年趋势看拐点；增速×企业爬坡对撞；下游驱动可持续性 | 看投资额/在建量先行指标拐点 | 必做 |
| 12 | 竞争格局 | 集中度CR3/CR5+分层；锚定2-3家可比公司；公司位势；威胁类型；竞争格局表 | 集中度高+非龙头=危险 | 必做 |
| 13 | 产业链定位 | 上游依赖度可替代性；下游集中度议价力；三方议价权 | 上游受制+下游强势=夹心层 | 必做 |
| 14 | 商业模式 | 销售模式×财务特征找矛盾；收入确认口径核验；盈利可持续性；模式×资源匹配 | 经销却应收高=赊销换销量 | 必做 |
| 15 | 估值合理性 | 可比公司PS/PE+DCF情景分析；理论市值区间；对撞本轮估值；是否透支未来 | 亏损用PS盈利用PE；已达上限没留容错=透支未来 | 必做 |
| 16 | 财务健康度 | 现金短债比；经营现金流正负趋势；负债率+周转；资金缺口 | 现金÷短债<1=高危 | 有财报必做 |
| 17 | 合规法律风险 | 失信/被执行/限高三查；行业必备资质；重大诉讼处罚；环保安全专项；AI/数据合规 | 失信/限高/冻结=一票否决 | 必做·红线 |
| 18 | 落地可行性 | 产能利用率假设验证；产值逐年爬坡曲线；载体真实性；企业自投比；多地并行 | 市占率0.1%却假设63.7%利用率=路径不清晰 | 必做 |
| 19 | 国资政策合规 | 以投促招政策符合性+评分标准；审批权限金额阈值；六大红线；资金出境 | 明股实债/保底承诺=红线 | 必做·红线 |
| 20 | 地方匹配度 | 主导产业匹配；贡献量化可实现性；阶段×基金定位；政策工具清单 | 贡献要量化不照单全收 | 必做 |

## 四、估值方法论（D15详细打法）

### 可比公司法

1. 找2-3家同行业已上市公司（D12已锚定的可比公司）
2. 取PS（亏损公司用）或PE（盈利公司用）
3. 对未上市早期公司打折价：流动性折价、治理折价、财务不透明折价、客户集中度折价
4. 给出前瞻收入倍数区间，乘以目标公司预期收入=理论估值区间

### DCF情景分析（即使无财报也做）

当无审计财报时，基于行业规律做情景假设：
- 收入预测：基于已有收入+行业增速，分熊/基/牛三档
- EBIT利润率改善路径：从当前（推断）逐步改善到行业稳态
- 折现率：反映早期公司高风险（通常20%-26%）
- 永续增速：2%-4%
- 输出WACC×永续增速的敏感性矩阵
- 熊/基/牛三档对应的EV区间

### 估值判断标准

- 本轮估值落在区间下限→合理
- 落在区间中位→需更强证据支撑
- 显著高于上限→偏贵，追问溢价依据
- 已透支3-5年预期→容错空间小

## 六、评级口径与阶段差异化

### A/B/C/D 评级
| 评级 | 含义 | 适用情形 |
|-|-|-|
| A 建议推进 | 较强投资或招引价值 | 业务清晰、数据可信、估值合理、落地贡献明确、风险可控 |
| B 谨慎跟进 | 有亮点但需会面核实关键信息 | 赛道好但估值/财务/订单/落地承诺的推断需会面验证 |
| C 储备观察 | 暂不进实质投资流程 | 早期、数据不足、落地价值不清但有长期观察价值 |
| D 暂缓或不建议 | 当前不具备推进条件 | 估值明显偏高、财务风险突出、承诺不可实现、合规/落地障碍大 |

### 阶段差异化研判重点
- **成熟期**：看估值合理性、盈利质量、退出路径、落地贡献。重点维度 08/15/16/20。
- **成长期**：看增长可持续性、客户验证、融资节奏、竞争位势。重点维度 05/08/12/09。
- **早期**：看技术真实性、团队能力、工程化路径、后续融资能力。重点维度 06/07/05/10。

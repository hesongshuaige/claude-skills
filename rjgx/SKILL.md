# 国企人际关系处理框架 v2.2

## Overview

RJGX is a state-owned-enterprise workplace relationship skill. It turns ambiguous relationship situations into a diagnosis, strategy, wording, risk check, and optional follow-up plan.

Core rule: **诊断 → 匹配 → 出话术 → 三问自检。禁止跳过诊断直接套模板。**


## When To Use

Use this skill when the user needs help with:
- 向上管理：汇报坏消息、争取资源、婉拒领导任务、让领导觉得“有思路”。
- 向下管理：批评下属、拒绝下属诉求、绩效面谈、推进执行。
- 横向协作：跨部门配合、厘清边界、拒绝不合理诉求、协调资源。
- 国企或强层级组织中的面子风险、权力动态、人情债、组织口径和话术。
- 把一次沟通经验沉淀为可复用 SOP。

Do not use this skill as the primary answer for:
- 法律、纪检、劳动仲裁、心理治疗、危机干预。本技能只能给沟通策略，不能替代专业意见。
- 操纵、栽赃、造假、威胁、羞辱、绕过合规或隐瞒重大事实。
- 单纯公文、新闻稿、投研材料或会议纪要，除非核心问题是人际关系和组织表达。
- 低风险小修改。此类任务直接给精简话术并做三问自检。

## Six-Layer Use

Use the smallest frame that can still be checked:
- **Small**: Context + Procedure + Verification. Use for一句话润色、临场拒绝、简短提醒。
- **Standard**: Context + Source + Procedure + Harness + Verification. Use for批评、汇报坏消息、跨部门协调。
- **Full**: Context + Source + Procedure + Harness + Verification + Iteration. Use for合规红线、绩效处分、领导决策、对外表达、长期关系修复。

Memory anchor: 先诊断场景和边界，再确认事实依据，再匹配策略出话术，再套过程护栏，最后按面子、关系、出口验收；高风险或反复发生的场景要复盘沉淀。

## Source Authority

Default source priority:
1. User-provided facts: exact words, relationship, setting, time, desired outcome, organizational background.
2. Authorized materials: policies, procedures, meeting notes, performance rules, role responsibilities, department division.
3. This skill's framework: mixed relationships, face-risk diagnosis, renqing debt, power dynamics, scenario playbook.
4. General communication or management theory. Use only as support.
5. AI inference, rumors, and emotional judgments. Treat as hypotheses, not facts.

Conflict rules:
- Concrete facts beat general theory.
- Organizational rules beat personal feelings.
- Compliance boundaries beat face-saving strategy.
- If facts are missing, make a conservative assumption and name it. Ask only when missing identity, setting, or target outcome would reverse the strategy.

## Quick Intake

When the user gives a vague request, identify four facts before drafting:

1. **Person**: superior, subordinate, peer, other department, external partner.
2. **Situation**: bad news, criticism, refusal, resource request, boundary issue, performance issue.
3. **Setting**: public/private, written/oral, formal/informal, third parties present.
4. **Goal**: repair relationship, push execution, protect boundary, get support, report risk.

If time is urgent, do not over-question. Give a safe temporary line, then add what should be clarified afterward.

Ask at most three questions:
- 对方是谁，和你是什么关系？
- 这句话是在什么场合说，公开还是私下？
- 你最想达成的结果是什么？

## Diagnosis

### 1. Face Risk

Diagnose what face is at stake:
- **Moral face**: integrity, loyalty, character, corruption, fairness. Highest risk. Do not imply misconduct unless the user has verified facts and a formal process.
- **Competence face**: judgment, ability, professionalism. Challenge privately, concretely, and through facts.
- **Social face**: public rank, status, dignity in front of others. Protect publicly; handle substance privately.

Escalate risk when:
- Third parties are present.
- A superior or subordinate is present.
- The other party was recently publicly denied.
- The issue affects their own reporting chain.
- The likely retaliation path includes complaint, report, or organizational procedure.

### 2. Relationship Type

Classify the relationship:
- **Emotional**: rare in SOE work; use need-based support carefully.
- **Instrumental**: no trust or history; use fairness, roles, and boundaries.
- **Mixed**: default for most SOE internal relationships; use face + renqing + practical exchange.

Do not over-intimacy a mixed relationship, and do not turn a long-term mixed relationship into a cold transaction unless boundary protection requires it.

### 3. Power Dynamic

Check:
- Who is more replaceable?
- Who can make the other side uncomfortable elsewhere?
- Whose result is affected more by this issue?
- Does the matter cross departments, leaders, HR, finance, audit, legal, or discipline inspection?

## Strategy Router

Use the diagnosis to route:

- **Superior / leader**
  - Bad news: give face, state changed facts, attach options, return decision space.
  - Resource request: frame as company benefit, cost of inaction, specific ask.
  - Cannot or should not do a task: recognize direction, explain structural mismatch, offer alternative, return decision.
  - Show thinking: classify, explain root cause, state judgment.

- **Subordinate / team**
  - Criticism: use behavior-impact-consequence-close; private first.
  - Refusal: validate reasonable part, explain objective constraint, offer alternate path.
  - Performance talk: affirm person, state rule, use data, give recovery path, preserve working relationship.
  - Execution push: public praise, private correction, pair criticism with next action.

- **Peer / department**
  - Need cooperation: create or invoke renqing, frame shared benefit, reduce their cost.
  - Clarify boundary: use procedure, responsibility map, meeting decision, or audit-safe language.
  - No relationship debt: first make a small concession or invoke legitimate superior/meeting intent.

## Wording Formula

Default formula:
1. Give face: acknowledge contribution, intent, pressure, or reasonable basis.
2. State facts: concrete behavior, changed condition, rule, data, or boundary.
3. Give step: option, next action, coordination path, or fallback.
4. Leave exit: let the other side preserve dignity and know what to do next.

Never use wording that:
- Labels a person: "you are irresponsible", "you have no ability", "you have bad motives".
- Publicly forces the other side into a corner.
- Invents a leader's instruction, meeting decision, system rule, or department commitment.
- Covers up legal, audit, financial, disciplinary, HR, or public-disclosure risk.

## Harness

Relationship guardrails:
- Do not prioritize winning one conversation over preserving long-term cooperation.
- Do not treat a mixed SOE relationship as pure transaction by default.
- Do not encourage public humiliation, revenge, threat, or old-score settling.
- Tie face-giving to facts, procedure, organization benefit, or future cooperation.

Face guardrails:
- Moral face is the highest risk; avoid implying corruption, character defects, disloyalty, or malicious intent.
- Competence criticism must be concrete and private.
- Social face must be protected in public settings.

Fact guardrails:
- Do not fabricate facts, data, meeting decisions, policies, leader opinions, or commitments.
- Mark uncertainty explicitly: "我先按……理解"; "如果事实是……则……".
- Compliance risk cannot be softened away by wording.

Output guardrails:
- If the user asks for wording, give wording first and analysis second.
- If the user asks for strategy, give judgment first, then path and wording.
- Serve the current scenario only; do not list every possible playbook.
- In Feishu/Lark chat output, do not use Markdown tables. Use short sections, numbered items, or emoji anchors.

## Verification

Before finalizing, run these checks:

1. **Face**: Will the other side feel publicly embarrassed, morally accused, or personally attacked? If yes, rewrite.
2. **Relationship**: Will this push a long-term mixed relationship into cold transaction or confrontation? If yes, add renqing, face, or a cooperative exit.
3. **Exit**: Does the other side know the next step and have a way to step down? If not, add a concrete action.

High-risk extra checks:
- **Fact**: Are key facts from the user or authorized sources? Did any guess become a fact?
- **Compliance**: Does this involve funds, audit, discipline, HR, dismissal, public release, or reporting? If yes, mention formal process or professional advice.
- **Setting**: Is the wording appropriate for public/private and written/oral use?
- **Authority**: Does the reply overstep leadership, HR, legal, finance, audit, or discipline-inspection authority?

Minimum acceptable output:
- Diagnosis conclusion.
- Strategy direction.
- Directly usable wording.
- At least one risk reminder or alternate phrasing.
- No Markdown tables in Feishu/Lark-facing output.

## Iteration

When the user reports what happened after using the wording:
- Record actual reaction, relationship change, and task progress.
- Diagnose whether failure came from wrong relationship type, missing facts, wrong setting, excessive softness/hardness, or unclear exit.
- Update the strategy, not just the sentence.
- If similar cases repeat, suggest a personal SOP: trigger, opening line, forbidden wording, escalation path, and verification checklist.

Do not generalize one successful sentence into a universal template. Reuse the diagnosis logic, risk boundary, and wording structure.

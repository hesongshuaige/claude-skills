## 已验证案例：批评彭杰（向下·BIC批评法）

场景：何松让彭杰发绩效考核通知。彭杰说内容有问题要改一下再发。何松说“和其他部门负责人沟通好就行，发不发无所谓。”结果彭杰既没发通知，也没沟通部门长，到晚上九十点都没动静。

诊断：
- 关系类型：混合性，上下级，有工作交情。
- 面子风险：彭杰曾说“你写的让大家觉得事情很多”，这挑战了何松的能力面子。批评时不能把靶心放在“你质疑我”，否则会被理解成报复。
- 策略：只打“承诺不兑现 + 中间不反馈”，保护道德面子和能力面子。

可用话术骨架：

“彭杰，你先坐。昨天那个事我要跟你说一下，但不是因为你提意见。你对通知内容有自己的想法，这件事本身没问题，愿意动脑筋是好事。

我说的是另一件事：你承诺了要做的，没有做；中间也没有任何反馈。

我当时说‘和其他部门负责人沟通好就可以了，发不发都无所谓’，意思是沟通比通知重要，通知只是形式。但你理解成两件事都可以不做。

这不是能力问题，是习惯问题。你现在是综合部骨干，将来如果独立负责一摊事，这种‘接了就沉了’的习惯，对你的发展是障碍。

以后接到任务，如果你觉得要调整，咱们当面碰掉。改通知也好、换方式也好，都行。但一旦定了或者你点了头，时间节点就是铁打的。中间卡住了要跟我说。

这个要求你能不能做到？能做到这个事就翻篇。通知今天发掉，部门长今天沟通掉。”

复盘要点：
- 开头“不是因为你提意见”：保护自己的面子，同时降低对方防御。
- 靶心精准：Behavior（没发 + 没沟通）→ Impact（事情消失）→ Consequence（影响发展）。
- “不是能力问题，是习惯问题”：保住能力面子，同时把问题钉住。
- “能不能做到 → 翻篇”：给出口，让关系继续流转。

## Agent 常见失败模式

1. 跳过诊断直接套模板。用户说“帮我写一段批评 XX 的话”，Agent 不问事实、场合、关系，直接套 BIC。
2. 在飞书对话中使用 Markdown 表格。飞书渲染效果差，应使用分段、编号、emoji 锚点。
3. 话术太长太啰嗦。真实对话中没人照读完整长稿，应裁剪成自然语言。
4. 同一回复给太多策略。用户只问一个场景，就只服务当前场景。
5. 不敢判断。能基于已知信息保守判断时，不要反复追问。

## 输出格式铁律（飞书对话专用）

飞书对话中禁止使用 Markdown 表格。对比、分类、排行信息用 emoji 锚点、短标题、编号或清晰分段。

正确示例：

🥇 **情感性关系**：需求法则，不分彼此，全力满足。
🥈 **工具性关系**：公平法则，算清楚，不亏不欠。
🥉 **混合性关系**：人情法则，给面子、做人情、等回报。

正反话术示例：

❌ “这个咱们做不了。”
✅ “这个方向逻辑上讲得通，但人员配置和事务复杂度之间有结构性错位。建议先试点跑通再铺开，您看行不行？”

内部 reference 可以使用表格；面向飞书用户输出时不要使用 Markdown 表格。

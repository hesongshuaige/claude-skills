# 诸葛资本董事长文稿写作

## 1. 定位

本 Skill（技能）用于为诸葛资本董事长起草、修改、审核各类公司文稿和工作推进方案。核心风格是：

**务实、辩证、边界清晰、数据说话。**

目标不是写得漂亮，而是让董事长拿来就能用、少改、不错位、不冒进。材料必须体现董事长的工作判断习惯：先看真实底数，再看堵点打法，最后看需要谁协调、下一步怎么干。

## 2. 适用与不适用

### 适用

- 董事长讲话稿、发言稿、汇报材料、报送文件、人大政协提案答复。
- 对内材料：向书记、国资局、主管部门、内部会议汇报。
- 对外材料：人大政协调研、行业交流、招商推介、公开 PPT 文案。
- 向上争取材料：专报、请示、争取指标认定、争取政策或资源支持的材料。
- 董事长交办事项推进方案：工作方案、推进清单、复盘分析、需协调事项清单。
- 已有初稿的审改、压缩、改口径、改成口头要点稿。

### 不适用

- 不代表诸葛资本或董事长立场的普通公文。
- 需要披露未公开项目、估值、谈判条件、对赌条款、内部决策细节的对外材料。
- 用户没有说明“谁讲、对谁讲、什么场合”的正式稿。缺关键信息时先追问，不直接写。

## 3. 最高优先级

规则冲突时按以下顺序执行：

1. **权责边界**：不得替主管单位表态，不得抢上级功劳。
2. **场合路由**：先判断对内知己、向上争取、对外公开，还是普通书面材料。
3. **主题咬合**：材料必须回答会议、通知、提案或调研主题。
4. **数据真实性**：没有来源的数据和结论不得写死。
5. **语言精炼**：写完必须删水分、删重复、删空话。

## 4. 动笔前必问

正式材料动笔前必须先确认以下信息。用户已提供的，简要复述确认；没提供的，追问。

### 必须确认，缺一项不能直接成稿

1. **文稿类型**：讲话稿、汇报材料、专报、提案答复、报送文件、PPT 文案、推进方案，还是审改已有稿。
2. **使用模式**：对内知己、向上争取、对外公开，还是董事长交办事项推进。
3. **角色定位**：诸葛资本是主牵头单位，还是参与单位、经办单位、被调研单位。
4. **对象和场合**：谁听、谁看、会议主题是什么、是否公开发布。
5. **依据材料**：会议通知、议程、提案原文、领导口径、项目台账、公开 PPT、官网内容、历史稿。

### 可缺省，但要标注假设

- 篇幅、发言时长、是否需要口头要点版。
- 是否有统一数据口径。
- 是否需要建议部分。
- 是否有不能写的敏感信息。
- 哪些事项需要董事长协调、拍板或出面。

## 5. 场合路由

### 三类模式总开关

先按以下三类判断，不要把“向上争取”和“对外公开”混在一起：

| 模式 | 典型场景 | 写法重点 |
|---|---|---|
| 对内知己 | 给董事长、班子会、内部复盘、内部草稿 | 直接讲底数、缺口、堵点、责任和方案 |
| 向上争取 | 给主管部门、上级单位的专报、请示、争取支持函 | 先讲成果和基础，再讲卡点和支持事项 |
| 对外公开 | 人大政协调研、行业会议、招商推介、公开 PPT | 只用公开宏观口径，正面展示，不披露内部明细 |

“摆平”不是包装事实，更不是编造进展。它的正确含义是：在真实底数基础上，把问题表达成“已有基础 + 当前卡点 + 解决方案 + 需支持事项 + 预期贡献”。

### 对内知己材料

用于书记汇报、国资局报告、内部总结、主管部门正式材料。

写作要求：

- 开场可以直接讲缺口、堵点、差距，不要为了好看弱化问题。
- 数据按“穷尽原则”处理：相关项目、收益、产值、分类尽量统计全；缺数据要标注“待补充”，不能假装没有。
- 关键数据必须标注来源部门和核对状态，例如“来源：招商部台账，状态：待财务复核”。
- 结构用“双轮驱动”：产业贡献和财务回报并列，不写成两张皮。
- 产业贡献先讲总量，再按产业类型或“5+5+4”等既有框架分类，最后选典型项目作例子。
- 财务回报单独成段，讲累计收益、账面浮盈、累计回报等已确认指标。
- 下步打算必须同时回答两件事：如何进一步支撑产业，如何提升财务回报。
- 可以讲问题短板，但必须配应对方向，不能只摆困难。
- 涉及推进、协调、拍板的事项，必须单列“需董事长协调/拍板事项”。

推荐结构：

```text
一、投资成效：产业支撑和财务回报双轮驱动
（一）产业贡献：总量、分类、典型项目
（二）财务回报：收益指标、回报质量、辩证关系
二、下步工作打算
（一）优化基金布局，强化产业支撑
（二）加强财务投资，提升回报质量
三、需董事长协调/拍板事项
```

可用核心表述：

```text
在确保发挥产业支撑和培育增量作用的前提下，兼顾国有资产保值增值和市场化回报。
```

### 向上争取材料

用于向主管部门、上级单位报送专报、请示、争取指标认定、政策支持、资源倾斜。

写作要求：

- 开头不写问题清单，先写已完成的基础、已形成的成果、可继续放大的贡献。
- 缺口和短板不能隐瞒，但要写成“当前卡点、需支持环节、解决后贡献”。
- 每个诉求必须有依据：投入事实、规则依据、项目支撑、数据测算或上级政策口径。
- 不得替主管单位表态，不得写“统筹全市”“确保解决”等越位承诺。
- 需要支持的事项必须具体到部门、规则、指标、资源、节点或协调动作。

推荐结构，使用“橄榄型”：

```text
第一，已形成的工作基础和阶段性成果。
第二，正在推进的重点项目和对冲方案。
第三，当前需协调支持的具体事项。
第四，获得支持后的共同贡献和表态。
```

表达转化规则：

| 内部说法 | 向上争取写法 |
|---|---|
| 缺口很大 | 需重点攻克的提升空间 |
| 要回 30% 指标 | 建议确认我方 30% 归属，落实“谁投入谁受益”原则 |
| 项目推进不了 | 项目当前处于 X 环节，协调解决 Y 后可进入快车道 |
| 我们缺 XX 资源 | 为实现 XX 更高目标，恳请在 XX 上给予支持 |
| 暂无客户 | 正在加快客户导入，具体进展以招商部门核实口径为准 |

以上表达涉及数字、客户、时间、指标归属时，必须有来源材料；没有来源时用 `<待确认>` 标记，不得写死。

### 对外公开材料

用于人大政协调研、行业会议、招商推介、公开 PPT 文案、外部交流。

写作要求：

- 只用公开、宏观、已核实数据，例如总产值、总收益、整体回报率。
- 不写具体未公开项目名，不写过细分类，不写内部策略细节。
- 以正面展示为主，默认不讲问题短板，除非用户明确要求。
- 公司品牌表述要自然融入，不硬塞。
- 建议部分必须贴合调研主题和公司真实痛点；没有合适建议可以不写。
- 不主动展开内部短板；确需提及时，用事实、方案和支持事项表达。

推荐结构，强制四段式：

```text
第一，公司基本情况。
第二，基金如何面向产业布局，并与调研主题挂钩。
第三，针对性建议。
第四，表态收尾。
```

可自然融入的品牌口径：

- “一主导产业一基金”的布局逻辑。
- 打造高能级“朋友圈”的项目来源和产业协同意图。
- 诸葛资本作为“竞争型国企”的目标定位。

### 提案答复

提案答复必须先拿到提案原文或摘要，再逐条对应。

写作要求：

- 先回答提案关切，再讲公司工作。
- 不能把通用汇报稿搬过来。
- 需要体现“已做什么、正在做什么、下一步怎么回应建议”。
- 诸葛资本如果不是主管单位，必须写清“在 XX 局指导下”“配合 XX 部门”等边界。

### PPT 文案

PPT 文案按对外公开材料处理，是讲话稿的精简版。

写作要求：

- 每页只放一个核心判断。
- 标题先给结论，正文只放支撑数据和关键词。
- 不放内部明细、不放长段落、不放未核实数字。

### 董事长交办事项推进方案

用于董事长要求拿方案、抓推进、做复盘、列清单的任务。

推荐结构：

```text
一、目标和判断：这件事要解决什么问题
二、当前底数：已有基础、数据来源、核对状态
三、主要堵点：卡在哪里、影响什么结果
四、推进打法：责任人、时间表、关键动作
五、需董事长协调/拍板事项
六、下一步建议
```

方案必须避免泛泛表态。每个动作尽量落到责任部门、时间节点、交付物或核验标准。

## 6. 主题咬合

凡是有明确会议主题、调研题目、提案内容、通知要求的任务，必须执行：

1. 摘出主题中的关键词和问题。
2. 建立“主题问题 → 公司回应内容”的对应关系。
3. 正文至少一次点明与主题的关系。
4. 如果用户没给原文，先索要；用户暂时没有时，只能写“基于当前信息的框架稿”，并标注待核。

## 7. 语言规则

- 写给董事长的是口语化要点稿，不是广播稿。
- 多用短句，一段只讲一个意思。
- 先讲结论，再讲数据和例子。
- 必须使用“第一、第二、第三”或“首先、其次、下一步”等序数词。
- 同一专有名词不要反复解释；“5+5+4”等术语只在最必要处出现一次。
- 禁止空话套话、形容词堆砌、无数据判断。
- 禁止“大概、可能、好像”等没底气的词。
- 不要在不同位置重复同一个意思。

篇幅参考：

| 类型 | 篇幅 |
|---|---|
| 对外常规发言 | 4-6 页或按用户时长折算 |
| 对内深度汇报 | 按主题决定，但仍要精炼 |
| 紧急极简版 | 1-2 页，只列核心要点 |

如场合允许，优先提供两版：

- 详细书面版：供存档和参阅。
- 精炼口头要点版：供董事长现场发言。

## 8. 风险红线

出现以下情况必须拦截或改写：

- 让诸葛资本替主管单位表态、替上级承诺、抢上级功劳。
- 经办单位材料没有写“在 XX 局指导下”等前置边界。
- 对外披露内部项目谈判细节、估值、对赌条件、未公开基金安排。
- 对其他单位作评价，尤其是产投、科创投等平行或相关单位。
- 编造数据、项目、领导表态、政策依据、收益结果。
- 使用“稳赚、保本、保证解决、一定落地”等绝对化表达。

不清楚边界时，先问清楚；必须先交稿时，用 `<待确认>` 标记，不写死。

## 9. 输出格式

默认输出顺序：

1. **前置判断**：使用模式、文稿类型、角色定位、主题咬合、数据来源状态。
2. **需确认事项**：只列真正影响口径和风险的事项。
3. **正文稿**：按对应结构输出。
4. **口头要点版**：用户需要发言时提供。
5. **自检结果**：简要列出通过项和待确认项。

凡涉及推进、争取、协调、决策的材料，必须额外列出：

- **下一步建议**：建议形成专报、报备、开协调会、补数据、约谈项目方等。
- **需董事长协调/拍板事项**：只列董事长确实需要出面的事项，不把部门日常工作上交。
- **数据来源和核对状态**：已核实、待业务部门核实、待财务复核、仅为初步测算。

如果用户要求“只要正文”，可以省略前置说明，但仍要在内部执行判断和自检。

## 10. 交付前自检

提交前逐项检查：

- 对内知己、向上争取、对外公开或推进方案的模式判断正确了吗？
- 角色定位正确吗？有没有越位？
- 有没有紧扣会议、通知、提案或调研主题？
- 数据口径对吗？对内尽量全，对外只取公开宏观口径。
- 有没有体现产业贡献和财务回报的辩证统一？
- 结构是否匹配文稿类型？
- 口语化程度是否适合董事长发言？
- 有没有重复术语、重复观点、套话空话？
- 有没有没来源的数字和判断？
- 涉及推进、争取、协调、决策时，是否列出下一步建议和需董事长协调/拍板事项？
- 数据是否标注来源部门和核对状态？
- 系列材料的数据口径和核心打法是否一致？

任一关键项不通过，不得装作完成；必须修改、标注待确认，或向用户追问。

## 11. 维护规则

当用户提供董事长改稿、最终采用稿、最新数据口径、公司公开 PPT、官网新口径时，优先将其作为更高权威来源。若新口径与本 Skill 冲突，以用户指定的最新正式口径为准，并建议更新本 Skill。

修改本 Skill 后，用 `references/pressure-scenarios.md` 中的场景做轻量测试，避免退化。

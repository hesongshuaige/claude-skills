# skillyes REFERENCE

## §一 9 类速查表（定类用）
| 类 | 一句话 | 典型任务动词 |
|---|---|---|
| 写作 | 写/改/翻译成文 | 写、改、翻译、润色 |
| 拆解 | 把复杂东西拆开看 | 拆解、提取、梳理 |
| 分析 | 分析判断给结论 | 分析、评估、诊断 |
| 开发 | 写代码/技术 | 实现、调试、生成代码 |
| 驾驭 | 驾驭 AI/核对 | 核对、互检、驾驭 |
| 决策 | 帮做决定 | 决策、取舍、排优先 |
| 设计 | 设计结构/方案 | 设计、规划、搭建 |
| 学习 | 学/记/练 | 学习、记忆、练习 |
| 框架 | 套方法论框架 | 套用、按框架、结构化 |

定类规则：看用户问题的主要动词 → 映射到上表。跨类（如"分析报告并改写成推文"）按**主要动词**定主类（这里是"改写"→写作），次类（分析）在"同类延伸"里带出。

⚠️ 条目数会变（库持续增长，以索引页实际为准），不硬编码条数。

## §二 匹配打分细则
0. **先读索引页顶部「🎯 按需求速查」导航定类**，再跳到该类区块细读（索引页可能很大，全读费 token，按类缩小范围）。
1. 拉索引页全文（`scripts/fetch_index.sh`）。
2. 读条目，每条 6 字段：🔗链接 / 干啥 / 什么时候用 / 你给它 / 它给你 / 关键词。
3. 用户问题 → 提取意图关键词（场景词 + 任务词）。
4. 定类（§一）后，类内每条按 4 维打分（0-2 分，共 8 分）：
   - 关键词重合度（权重最高）
   - "什么时候用"场景贴合度
   - "你给它"输入契合度
   - "它给你"输出契合度
5. top1 = 最佳；同类 top2-3 = 延伸候选。
6. 同分处理：关键词重合度高的优先；仍并列给 2 条让用户选。

## §三 学习法详解
### 默认·样例+变式对比（5-8 分钟）
1. **拆骨架**：把最佳提示词拆成 [角色 / 任务 / 约束 / 输出格式 /（可选）校验位]。
2. **抽模板**：占位符化成「这类问题的通用骨架」（如「你是【角色】，根据【输入】，按【约束】，输出【格式】」）。
3. **变式对比**：拉同类 2-3 条，用表格标「不变的本质（如都要给角色+约束） vs 可变的皮（如输出格式不同）」。
4. **烂 vs 好**：给 1 组「乱问的烂写法」（如只说"帮我写个方案"）vs「库里的好写法」，让用户直观感受差的在哪。

### 脚手架渐隐（按 progress.json 阶段）
- 阶段 1（首次遇这类）：给完整模板，让用户照填占位符（抄）。
- 阶段 2（同类第 2 次）：给半成品（删掉关键约束段），用户填空。
- 阶段 3（同类第 3 次+）：用户独立写一条，AGENT 按「骨架完整性 + 约束齐全」点评（不判业务对错）。

### 可选升级（用户说"深入"才切）
- **真费曼**：让用户用自己的话复述"这提示词为啥这么设计"，AGENT 找讲不清的地方追问。
- **练习式**：AGENT 给一个类似新问题，用户照框架自己写一条，AGENT 点评。

## §四 progress.json schema
```json
{
  "version": 1,
  "用户学过的类": {
    "写作": {
      "阶段": 2,
      "首遇": "2026-07-27",
      "最近": "2026-07-29",
      "学过的条目": ["【写作】写一封XX.md"]
    }
  },
  "最后更新": "2026-07-27"
}
```
- 路径：与 SKILL.md 同目录的 `progress.json`（首次教学时创建）。
- 阶段 = 该类被呈现（第 4 步）的次数，封顶 3。
- 首次创建：第 5 步教学时若文件不存在则创建，初始 `{"version":1,"用户学过的类":{},"最后更新":"<today>"}`。
- 每次第 4 步呈现后：对应类 `阶段 += 1`（封顶 3）、`最近 = <today>`、`学过的条目` 加入本次最佳条目名。
- ⚠️ 日期不能用 `Date.now()`（脚本里禁止），由执行 LLM 用当天日期写入。

## §五 lark-cli / token 坑
- **PATH**：非交互 shell 要先 `export PATH="$HOME/.npm-global/bin:$PATH"`，否则 `lark-cli: command not found`。
- **fetch 取值**：`markdown +fetch` 取 `.data.content`（不是顶层 `.content`）。
- **索引页 token**：从 `$SKILLYES_INDEX_TOKEN` 读（env 或 `~/.config/skillyes.conf`，见 README）。
- **两 token 别混**：`node_token` 拼 URL（`https://my.feishu.cn/wiki/{node_token}`）；`obj_token`（=file_token）fetch/overwrite 单条全文。
- **单条全文 fetch**：node_token **不能**直接 fetch（返回 null）。两步：
  1. 查 obj_token：`lark-cli wiki +node-list --space-id "$SKILLYES_SPACE_ID" --page-all | jq -r '.data.nodes[] | select(.node_token=="<该条node_token>") | .obj_token'`（注意是 `.data.nodes` 不是 `.items`，**必带 `--page-all`** 否则第一页空）
  2. 再 fetch：`lark-cli markdown +fetch --file-token <obj_token> | jq -r '.data.content'`
- **优化**：第 3 步匹配时一次性把全量 `node_token→obj_token` 映射存 `/tmp/skillyes_nodes.json`，后续第 4 步 fetch 直接查缓存，免每次全库扫。
- 改库/上传走 skillup，不在本 skill 职责内。

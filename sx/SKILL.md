# Tutorial Clarifier

## Overview

把"没讲透"的学习文章升级成"小白能看懂 + 专业可信 + 能落地"的版本。

核心来自实战验证过的"02 升级版"模式：故事开场 → 啥是 X → 对比表 → 真实示例 → 反例 → 专业小技巧 → 8 条检查清单。

## When to Use

**触发词（用户会说这些）：**
- "这篇教程没讲透 / 看不懂 / 跳过太多"
- "小白看不懂 / 太专业了 / 术语太多"
- "专业性可疑 / 命令像占位符 / 不真实"
- "看完不知道怎么动手 / 没例子 / 太抽象"
- "把这篇升级成大白话版"

**输入类型（啥文章都能升级）：**
- 技术教程、框架文档、API 指南
- AI 工具使用手册（Codex、Claude、Cursor 等）
- 公众号技术文章、技术博客
- 飞书知识库页面、学习笔记
- 课程讲义、培训材料

**不适用场景（按优先级判断，满足任何一条就跳过 02 模板）：**

| 场景 | 判断依据 | 正确做法 |
|------|----------|----------|
| 原文 < 500 字符 | commit message、代码注释、单行配置变更 | 原样保留，不套模板 |
| API 参考文档 | 参数表、函数签名清单、错误码列表 | 保留原结构，只补"术语 + 说白了" |
| 用户明确说"我要简短的" | 用户在 prompt 里说 short/简洁/简短 | 听用户的，5 段轻量版都不必上 |
| 纯翻译任务 | 用户说"翻译成中文"或"translate" | 翻译就别改了 |
| 已经按 02 模式写过的 | 已经有故事开场/说白了/检查清单 4 标记 | 跳过，再套一层会注水 |

**说白了：** 这 5 条是"宁可不升级也不要硬塞"的兜底。Karpathy 简单至上：能在 200 字解决的事别硬写到 2000 字。

## Core Workflow: 4 步升级法

### Step 1：扫描（5 分钟）

读原文，按"小白看不懂"和"专业性可疑"两类问题打标。

**小白类问题（5 类）：**
1. 术语没解释（如"sandbox""worktree""subagent"直接抛）
2. 没比喻/故事引入（上来就讲规则）
3. 抽象无落地（"做好边界"但不说怎么算好）
4. 缺对比/反例（只有"应该"没有"不应该"）
5. 没检查清单（学完不知道"学会没"）

**专业类问题（5 类）：**
1. 命令像占位符（`pnpm ...` 而非 `pnpm test -- src/auth.test.ts`）
2. 绝对化表达（"不许 push 主分支"而非"不直接 push"）
3. 工具名/版本错误（用 GPT-4 举例却写 GPT-5 命令）
4. 配置路径错误（写到 macOS 路径但用户是 Linux）
5. 缺失败案例（只讲 happy path，不讲翻车）

**完整自查清单** → `references/audit-checklist.md`

### Step 2：诊断（5 分钟）

给每个问题打分，定位要不要重写。

| 问题类型 | 出现次数 | 处理 |
|---------|---------|------|
| 小白类 | 3+ | 必加"故事开场 + 啥是 X" |
| 小白类 | 1-2 | 在原结构里补术语释义 |
| 专业类 | 1+ | 必改（命令具体化 + 软化绝对化） |
| 专业类 | 0 | 跳过 |

### Step 3：升级（30-60 分钟）

按 02 升级版模板重写。**严格遵守"不破坏原结构"原则**：

- 章节顺序、列表顺序、表格行数 **0 修改**
- 只能在原内容上**增补润色**
- 在开头加"故事开场"
- 在每个术语后补"说白了：X"（A+C 风格）
- 在每个抽象概念后加"啥是 X / 跟 Y 区别"小段
- 命令具体化：去 `...`、加真实参数
- 软化绝对化："不许 X" → "不直接 X"
- 末尾加"专业工程师的小技巧"4 条
- 末尾加 8 条"检查清单"

**完整模板** → `references/upgrade-template.md`

### Step 4：验证（5 分钟）

跑 4 件事确认升级成功：

1. **关键标记全在**：故事开场、说白了、检查清单、专业工程师的小技巧 4 个标记必须都出现
2. **专业命令可跑**：每个命令要可执行，不是占位符
3. **小白能读懂**：找 1 个真不懂的人读 3 分钟，问"你学到啥"——答得出来 = 通过
4. **结构未改**：原章节顺序、列表、表格行数对得上

## Quick Reference

| 任务 | 用啥 |
|------|------|
| 拿到一篇"没讲透"文章 | Step 1-4 跑一遍 |
| 不确定要不要重写 | Step 2 诊断表打分 |
| 升级中术语怎么补 | "说白了：X" 模式 |
| 升级中命令怎么具体 | 给完整命令 + 真实参数 |
| 升级中表达怎么软化 | "不许" → "不直接" |
| 验证升级效果 | 4 步验证 + 真小白读 3 分钟 |

## 信息广度怎么控？

skill 锁定的是"**结构稳定性**"和"**4 个关键标记**"（故事开场/说白了/检查清单/专业小技巧），**不锁定"信息广度"**。

**默认行为：** 聚焦原文 1 个主线，深度展开。

**想覆盖更多例子**（如多 server、多场景、多安全边界），在 prompt 里显式加：
> "请额外覆盖 [3 个常见变体 / 3 个典型场景 / 3 个安全边界]"

**想压缩成 cheatsheet**（如会议前的速查卡），在 prompt 里显式加：
> "压缩到 1500 字以内，保留 4 关键标记即可，删掉非必要模块"

**为啥这个很重要：** A/B 对照发现，无 skill 的 baseline 在"信息广度"上偶尔胜过有 skill（因为 agent 会自由扩展）。**这个段让 skill 用户有控制权**——既要 02 结构，又要广度时不需要修改 skill 本身。

**想指定段数（5 段轻量版 vs 7 段完整版）**，在 prompt 里显式加：

| 指令 | 适用 | 预期效果 |
|------|------|----------|
| "用 5 段轻量版" | 原文 < 1000 字、用户说"短一点"、命令清单型 | 强制 5 段结构，不注水 |
| "用 7 段完整版" | 原文 1000+ 字、深度教学 | 强制 7 段结构，全模块覆盖 |
| 不指定 | 默认行为 | agent 自动判断（**倾向 7 段**，因为"多写点更保险"是 agent 默认心理）|

**为啥要显式指定：** 实测发现 agent 不指定时倾向 7 段（即使原文 < 1000 字）。**用户要 5 段时必须在 prompt 里写明**，否则拿不到。

**推荐默认行为（按原文长度自动选）：**

```
[原文 < 500 字符]  → 不升级，原样保留
[原文 500-1000 字符] → 用 5 段轻量版
[原文 1000+ 字符]   → 用 7 段完整版
```

可以在 prompt 里直接复制上面这 3 行规则，让 agent 严格按字符数选段数。

## Implementation

**SKILL.md 主体（你正在读的）** — 4 步工作流 + 触发词 + 速查表
**references/upgrade-template.md** — 02 升级版 7 段结构模板 + 真实示例
**references/audit-checklist.md** — 小白 5 类 + 专业 5 类问题自查清单

## Common Mistakes

1. **硬塞"02 模式"到所有文章** — 不是所有文章都需要"故事开场"。**纯清单/参数表**（如 API 参考）保持原结构，只在术语后补"说白了"。
2. **改原结构（章节顺序/列表/表格行数）** — 用户硬要求 0 修改。只能在原结构上增补。
3. **专业小技巧 4 条凑不够就硬凑** — 凑不够可以只写 2-3 条。**质量 > 数量**。
4. **检查清单写得很抽象** — 必须可勾选（`- [ ] xxx`），不能是"做好准备工作"这种空话。
5. **忘验证** — 没跑 4 步验证就交付 = 不可信。

## Real-World Impact

**已验证场景**：Codex 大白话版 18 章节二次优化（00-17 全部升级，平均 +103% 字符，4 个关键标记 100% 命中，飞书 18 节点上传 + 验证 0 错误）。

**典型输入 → 输出**：
- 输入：1500 字符的"AGENTS.md 入门指南"（小白看不懂 + 命令像占位符）
- 输出：5500 字符的升级版（故事开场 + 5 模块详解 + 真实可跑命令 + 8 条自查 + 4 条小技巧）
- 时间：单篇 30-60 分钟

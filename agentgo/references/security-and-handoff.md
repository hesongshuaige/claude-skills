# 安全基线与 handoff（交接）

> **何时读取：** 写入凭据、扩大飞书权限、启用自动任务、交付或退役 profile（隔离档案）前读取。

## 1. 上线安全清单

- [ ] 每个 profile 使用独立模型凭据和独立飞书应用；禁止 clone（克隆）旧 `.env`。
- [ ] `FEISHU_ALLOWED_USERS` 使用明确 allowlist（白名单）；纯私聊禁用群聊，群聊默认必须提醒机器人。
- [ ] 应用 scope（权限范围）按当前功能最小化；先只读后写。
- [ ] 网关由普通用户运行，不用 root（超级用户），不因长连接开放公网端口。
- [ ] Linux 上 `.env` 权限为 `600`；Windows 仅允许运行账户和必要管理员读取。
- [ ] `approvals.mode`（审批模式）保持 `smart`（智能审批）或 `manual`（逐项审批），禁止 `off` 和 `--yolo`（跳过危险确认）。
- [ ] 密钥只在安全终端或专用密钥存储录入；仓库、技能、聊天、截图、报告、命令参数和普通日志零落地。
- [ ] 临时扫码/注册日志设为最小权限，验证后立即清理。
- [ ] 验证输出只显示变量名、是否存在和错误类型，不显示值。

## 2. 泄露响应

任何 App Secret（应用密钥）、模型密钥、用户令牌、设备码或服务器密码出现在聊天、普通日志、提交或截图中，都按已泄露处理：

核心动作是 rotate（轮换）或 revoke（吊销），不是只删暴露痕迹。

1. 停止使用相关凭据，必要时暂停对应网关或自动任务。
2. 在飞书或模型供应商控制台轮换/吊销；不要只删除消息。
3. 用户在安全终端更新当前 profile 的 `.env`。
4. 清理或脱敏临时日志、构建产物和未发布提交；保留不含秘密的事故审计事实。
5. 重启当前 profile，按模型、网关、消息、用户资源顺序复测。
6. 通知负责人：泄露范围、轮换时间、复测结果和仍未确认的风险，不复述旧值或新值。

## 3. 自动任务授权边界

| 情况 | 是否可直接执行 |
|---|---|
| 已明确授权，且目标、范围、频率、接收人完全不变 | 可以按既有批准继续，并保留运行证据。 |
| 新增任务或新数据源 | 必须先确认。 |
| 改变范围、频率、接收人或运行身份 | 必须先确认。 |
| 超出授权边界，或需要新增应用 scope/用户 consent | 必须先确认。 |
| 创建、更新、删除用户资源或变更权限 | 先确认对象、范围、后果；优先预演和可恢复方案。 |
| 已有预授权的事故响应流程明确允许自动轮换/吊销 | 仅在该书面边界内执行；否则先确认。 |

“用户曾让机器人工作”不等于授权所有未来计划任务。退役时也不自动删除旧 profile、机器人应用、服务、定时任务、历史会话、记忆或业务数据。

## 4. 不含密钥的完整交接清单

交接可以记录路径和标识的**类型/显示名**，不得记录真实 App ID、open_id（用户标识）、令牌、服务器地址、用户名或密钥值。

```text
交接状态：<已完成/部分完成/阻塞>
智能体显示名：<AGENT_DISPLAY_NAME>
一句话职责：<ONE_LINE_ROLE>
profile 名：<PROFILE_NAME>
profile 路径：<PROFILE_PATH_ON_TARGET_HOST>
workspace 路径：<WORKSPACE_PATH_ON_TARGET_HOST>
服务名：<GATEWAY_SERVICE_NAME>
飞书应用显示名：<FEISHU_APP_DISPLAY_NAME>
飞书域：<feishu-or-lark>
连接方式：websocket
允许用户：<白名单负责人/团队角色，不写真实 open_id>
群聊策略：<disabled/allowlist/open>
是否必须提醒：<true/false>
模型名：<MODEL_NAME>
模型供应商：<PROVIDER_NAME>
密钥变量名：<MODEL_KEY_ENV_NAME>, FEISHU_APP_ID, FEISHU_APP_SECRET
用户身份策略：<bot-only/user-default/not-configured>
已授权自动任务：<任务、目标、范围、频率、接收人>
已通过测试：<模型/网关/出站/私聊/群聊/用户身份/只读资源>
未通过或未验证：<分层列出>
尚未启用能力：<列表及启用条件>
最近验证日期：<YYYY-MM-DD>
状态命令：<先执行 --help 后使用的本机命令>
日志位置：<由当前 gateway status/help 确认的路径>
未决风险：<列表>
负责人：<ROLE_OR_TEAM>
```

## 5. 退役交接

- [ ] 先列出 profile、网关服务、飞书应用、lark-cli 授权、定时任务、会话、记忆和业务数据。
- [ ] 让用户逐项决定停止、保留、导出、吊销或删除。
- [ ] 默认只停止新增运行，不自动删除任何旧数据或应用。
- [ ] 删除和吊销必须使用本机 `--help`（帮助）核实命令，并再次确认准确对象与不可逆后果。
- [ ] 退役结果按层报告；“服务已停”不等于“凭据已吊销”或“数据已删除”。

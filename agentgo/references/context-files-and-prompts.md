# 上下文文件与提示词生成

> **何时读取：** 已创建 profile（隔离档案），准备从四个模板生成 `SOUL.md`、`AGENTS.md`、`README.md`、`PROJECT.md`，或排查规则未加载时读取。

## 1. 加载关系先定对

| 文件 | 推荐位置 | Hermes 加载规则 | 唯一事实来源 |
|---|---|---|---|
| `SOUL.md`（人格文件） | profile 根目录 | 存在时独立、始终加载；定义长期身份，不放项目流水账 | 长期人格、服务风格、判断原则、最高底线 |
| `AGENTS.md`（执行规则） | `terminal.cwd` 指向的 workspace（工作目录）根部 | **只读 cwd，不向父目录或子目录搜索** | 固定流程、工具规则、权限边界、持续授权、失败恢复、验收规则 |
| `README.md`（用户说明） | workspace 根部 | 供人阅读，不应被当成执行授权 | 能力三分组、触发方式、输入输出、最近验证证据 |
| `PROJECT.md`（项目状态） | workspace 根部 | 供人和智能体理解项目 | 目标、数据流、文件职责、总体状态、启用条件 |

`config.yaml` 必须明确：

```yaml
terminal:
  cwd: <PROFILE_DIR>/workspace
```

路径占位符必须替换为本机真实绝对路径；Linux 大小写敏感，Windows 盘符也要完整。不要把 `<PROFILE_DIR>`、`<WORKSPACE>` 或错误大小写留进最终文件。

## 2. 生成前问答

一次只问一个阻塞问题，收齐后再生成：

1. profile 名、智能体显示名和一句话职责是什么？
2. 主要用户、输入来源、输出目标是什么？
3. 哪些能力自动运行、哪些按需可用、哪些尚未启用？
4. 私聊、群聊、用户资源、写操作和定时任务的权限边界是什么？
5. 已授权自动任务的目标、范围、频率、接收人是什么？
6. 什么证据才算验收通过？失败时通知谁、停在哪一层？

用户没有回答的能力应写“尚未启用”或“待确认”，不能自行扩张授权。

## 3. 按四模板生成

只使用 `assets/templates/`（模板目录）里的四个模板，逐项替换其既有占位符；不要新造重复字段。

### `SOUL.md`

- 写长期身份、结论先行的表达、一次一个问题、事实与不确定性边界。
- 不写模型密钥、应用标识、具体计划任务或临时状态。
- 权限细则只引用 `AGENTS.md`；不要产生两个互相冲突的版本。

### `AGENTS.md`

- 写来源优先级、固定执行流程、幂等规则、权限边界、失败恢复和验证标准。
- 已授权自动任务只有在目标、范围、频率、接收人不变时可继续；新增任务、越界、写入、删除或权限变化必须先确认。
- 写敏感事故流程：停止使用、轮换/吊销、清理日志、通知负责人。

### `README.md`

- 严格分“自动运行 / 按需可用 / 尚未启用”。
- 每项写触发条件、输入、输出、运行身份/权限、最近验证证据；未启用项再写启用条件。
- 工具已装不等于业务能力已开；没有真实验证证据就写“未验证”。

### `PROJECT.md`

- 写目标用户、数据流、文件职责、当前状态、最近验证日期和未决风险。
- 档案与模型、飞书连接、自动任务分别标真实状态。
- 具体能力明细只维护在 `README.md`，避免双写漂移。

## 4. 动态上下文预算与编码

- 当前 Hermes 默认按模型上下文窗口动态计算单文件预算：20,000 字符是保守下限，较大窗口可增长；显式 `context_file_max_chars`（上下文文件字符预算）配置会覆盖动态值。
- 为跨版本、跨模型可移植性，仍把 20,000 字符作为默认保守目标，而不是固定硬上限。超过该目标前先拆成技能或独立参考，不删安全边界，并用当前版本实际日志/配置确认预算。
- 统一 UTF-8（通用中文编码）；Windows 向 Linux 传输时上传文件字节，不经 PowerShell（命令行）→ SSH（远程连接）的参数传中文正文。
- Windows 记事本若生成 BOM（字节顺序标记）导致配置异常，重新保存为无 BOM 的 UTF-8。

## 5. 生成后必须回读验证

- [ ] 从磁盘重新读取四个最终文件，不用生成前内存文本代替。
- [ ] 搜索所有 `{{...}}` 和 `<...>` 占位符，确认无残留。
- [ ] 每个文件优先控制在 20,000 字符内；若超过，已核对当前动态预算且确认没有截断警告。
- [ ] `SOUL.md` **只放在 profile 根目录**，workspace 不放副本，避免身份双源。
- [ ] `AGENTS.md` 位于 `terminal.cwd` 的准确目录。
- [ ] 启动一次新会话，让智能体复述职责、权限边界和工作目录，用来验证实际加载。
- [ ] 自动、按需、未启用三类能力没有互相矛盾。
- [ ] 文件不含 App ID、App Secret、模型密钥、令牌、服务器地址、真实 open_id 或本机专属绝对路径。

若使用 `--ignore-rules`（忽略规则）或 `--safe-mode`（安全排障模式），上下文可能被故意跳过；测试加载时不要带这些参数。

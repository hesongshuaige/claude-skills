## 一、举一反三场景池（**默认两个，可替换**）

> **说明**：以下两池是作者自用场景（新媒体 + 私募股权），skill 默认用这两个。如果你的行业不同，把下表整表替换成你行业的全链路场景即可（关键是要覆盖你业务从 0 到变现/交付的每个环节），其他流程不变。

围绕账号从 0 到变现的每个环节。常见场景：

| 环节 | 场景示例 |
|---|---|
| 标题/封面 | 爆款标题（小红书/公众号/抖音）、封面点击率、信息流主图 |
| 算法/流量 | 小红书推荐算法、抖音完播权重、视频号社交分发、公众号星标 |
| 短视频 | 前3秒钩子、完播率、脚本结构、口播节奏、B-roll |
| 选题/定位 | 选题差异化、追热点、人设打造、赛道选择、对标账号拆解 |
| 文案 | 朋友圈发售文案、小红书种草、公众号长文、短视频脚本、直播话术 |
| 私域/变现 | 社群发售、朋友圈剧本、引流路径、变现模型、定价策略 |
| 数据 | 数据复盘（看哪些指标）、AB测试、内容归因 |
| 互动 | 评论区运营、粉丝裂变、私域促活 |

### 池 B：私募股权 GP/LP（募投管退 + 内部全场景）

## 二、各类型验证标准（实测时对照）

| 类型 | 验证看什么 | 怎么测 |
|---|---|---|
| 学习类(苏格拉底) | ①一次一问 ②答错不给答案(用反问引导) ③答对追问更深 ④开场探测 ⑤口语化不分点 ⑥达标出毕业测试题 | M3 跑3轮：开场→故意答错→答对 |
| 文案类 | ①N条风格各异 ②无AI腔词(赋能/极致/打造/引领/助力/一站式/开启…之旅) ③字数符合(朋友圈<150) ④不编未承诺优惠 ⑤有转化引导 | M3 单轮生成，对照检查 |

| 生图类 | ①留白够(能后加文字) ②配色/质感符合要求 ③不糊不畸变 ④主体明确 | image-01 出图，人工判断 |

## 三、优化版规则模板（保留人设 + 补硬约束）

学习类（苏格拉底）通用 7 条：

1. 一次只问 1 个问题
2. 用提问引导我自己想通，**绝对不要直接把答案告诉我**
3. 答错时：严厉点出错在哪，但**绝对不要直接说正确结论**——用反问/类比引导我自己推
4. 答对时：简短肯定 + 追问更深一层
5. 开场先问 1 个探测问题摸底
6. 全程口语化，不用标题/分点/编号
7. 判断掌握后：一句话总结 + 立刻出真实场景应用题考我，不要问"要不要继续"

其他类型优化方向：

- **文案类**补：N条风格各异 + 禁AI腔词表 + 字数上限 + 优惠用占位符 + 转化引导
- **分析类**补：先体检数据 + 每结论附计算依据 + 标信心度 + 数据不足明说不硬编
- **生图类**补：明确"只要背景+留白" + 风格关键词锁质感 + "直接出图不要废话"

## 四、飞书上传流程（lark-cli）

**前置**：`SKILLUP_SPACE_ID` 和 `SKILLUP_INDEX_TOKEN` 已通过环境变量或 `~/.config/skillup.conf` 配好。

```bash
# 读配置（upload.sh 已自动做这步，这里展示逻辑）
[ -f ~/.config/skillup.conf ] && source ~/.config/skillup.conf

# 1. 上传 md（stdin 传内容）
FT=$(cat "<md文件>" | lark-cli markdown +create --as user --content - --name "<标题>.md" --format json 2>/dev/null | jq -r '.data.file_token')

# 2. 挂到库根
NT=$(lark-cli wiki +move --as user --obj-type file --obj-token $FT --target-space-id "$SKILLUP_SPACE_ID" --format json 2>/dev/null | jq -r '.data.node_token')
echo "URL=https://my.feishu.cn/wiki/$NT"

# 3. 更新索引页（overwrite，file_token 不变）
cat "<索引md>" | lark-cli markdown +overwrite --as user --file-token "$SKILLUP_INDEX_TOKEN" --content - --format json
```

**坑**（踩过，必避）：

- `--file` 拒绝对路径 → 用 `cat | --content -` 走 stdin
- `--name` 必带 `.md` 后缀，否则飞书不渲染
- `wiki +node-get` 用 URL 形式 `--node-token "https://my.feishu.cn/wiki/XXX"`（raw token 会报"--obj-type required"）
- M3 输出混 `<think>` 段：剥 `</think>` 后取正文；max_tokens 给 4096 防 think 吃光
- stdout 混进度行（"Running wiki move..."），jq 提取用 `.data.xxx`

## 五、MiniMax 脚本用法

- **M3 文本**：`python3 <repo>/scripts/verify_text.py scenes.json`（脚本内部调 MiniMax-M3，自写 messages 数组）
  - key 在环境变量 `MINIMAX_API_KEY`，或 `~/.secrets/mm.env`、`./.secrets/mm.env` 任一处
- **image-01 出图**：`python3 <repo>/scripts/verify_image.py --prompt "..." --out <路径> [--ratio 16:9]`
  - 生图 prompt **禁文字/人物/logo**（会糊）；只用 24h 有效 URL，脚本自动下载

# 迭代反馈协议

## 目标

当用户把 AI 初稿、领导改稿、同事改稿或最终定稿发回来时，Agent 要把反馈转成可复用经验。默认先分析和生成迭代卡，不自动改技能文件；只有用户明确要求“沉淀到技能”“更新 fyg”“写入规则”时，才写回 reference 并运行验证。

## 输入类型

| 用户给的内容 | 处理方式 |
|-------------|---------|
| 只有最终改好稿 | 反推可能的风格和结构规则，并标注“不确定，需要原稿对比” |
| AI 初稿 + 人工改稿 | 做差异分析，抽取明确规则 |
| 原始需求 + AI 初稿 + 人工改稿 | 完整复盘，可直接生成沉淀建议 |
| 多次同类改稿 | 判断是否升级为通用规则 |
| 用户只说“领导不满意” | 先追问不满意点，不直接编规则 |

## 迭代步骤

1. 判断材料类型：只有定稿、两稿对比、还是完整三件套。
2. 识别场景：会议发言、干部推荐、企业会见或其他。
3. 对比变化：结构、事实、语气、风险、口径、篇幅、开头结尾、身份姿态。
4. 归因：说明为什么这样改更好，避免只罗列差异。
5. 分类沉淀：分成“场景规则、禁用表达、推荐表达、领导偏好、单位口径、案例素材”。
6. 判断强度：一次出现默认为案例，重复三次以上才由 Agent 主动建议升级为通用规则；用户明确指定要迭代的内容不受三次门槛限制。
7. 输出迭代反馈卡；如用户要求写回，再修改对应 reference。

## 写回规则

只有满足以下任一条件，才能写回技能文件：

- 用户明确说“沉淀到技能”“更新 fyg”“写入 reference”“以后按这个规则”
- 用户已经完成分析，并明确指出“这条要迭代”“这类以后这样写”“把这个口径写进去”
- 同类修改已反复出现，且用户确认这是稳定偏好
- 这是风险类规则，例如收益承诺、干部任免、未公开项目、越权表态

写回位置：

| 规则类型 | 写入位置 |
|---------|---------|
| 座谈/汇报结构和表达 | `会议发言稿方法.md` |
| 组织推荐、人事口径 | `干部推荐材料方法.md` |
| 企业会见、招商接待 | `会见企业发言方法.md` |
| 固定模板句式 | 对应模板或方法文件 |
| 用户指定的一次性规则 | 可写入，但标注“用户指定规则”和适用边界 |
| 仅出现一次且用户未指定的案例 | 暂不写入通用规则，先输出迭代卡 |

## 安全边界

- 不把未脱敏的人名、项目名、金额、干部履历直接写入长期技能。
- 不把一次性领导偏好直接升级为通用规则；用户明确指定的除外，但必须标注来源和适用边界。
- 不把同事个人审美当成组织口径。
- 不覆盖原有规则；新增规则要说明适用场景和边界。
- 写回后必须运行 `skill-validator check <fyg 技能目录>`（skills 根目录下的 fyg 文件夹，路径因平台而异）。

## 输出要求

默认输出：

1. 先说“我从这版改稿里学到了什么”。
2. 给出 3-8 条可复用规则。
3. 标注哪些只是本次案例，哪些可升级为规则。
4. 列出建议写入哪个 reference。
5. 如果用户未明确要求写回，只给建议，不改文件。
